Offline architecture

Every write lands in the local database first and the UI updates instantly — internet is optional. The service worker caches the app shell so it opens even on a cold, offline start.

create invoice
→
App logic

→

< 10 ms
→

no network needed
SQLite WASM

Full relational engine in the browser — invoices, items, ledgers queried with SQL.

OPFS

Origin-private file system persists the SQLite file and attachments across sessions.

IndexedDB

Cache, settings, and the sync outbox of pending changes.

Local-first, like Vyapar desktop. The cloud is a sync target, never a dependency for day-to-day billing.

05

Multi-tenant database & metadata engine

One Postgres, many companies — isolated by tenant_id and RLS. Business behaviour is data, not code: a business type defines field metadata, which generates forms, invoices, and reports. New verticals ship without a deploy.

Tenant isolation
tenant_id: ASharma Medical
tenant_id: BAnand Restaurant
tenant_id: CKiran Mobiles

RLS ensures every query is scoped to the caller's tenant — no cross-company reads, enforced in the database.

06

Security & encryption

Zero-knowledge by design. Each company holds its own key; invoices are encrypted on-device before they ever leave. The cloud stores ciphertext it cannot read — and neither can Vyora's staff.

derived · never leaves device
→

Supabase

App owner cannot view customer invoices. Even Vyora's own staff see only encrypted blobs — a core differentiator.

RLS + JWT scope every request to one tenant TLS in transit · encryption at rest Role-based access: Owner, Manager, Cashier, Accountant…
