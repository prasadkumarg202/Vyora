V Vyora API Specification · Doc 06

A thin sync API over an encrypted, offline-first client

The client is the source of truth; the API exists to move encrypted record envelopes between devices, run privileged server-only jobs (GST filing, OCR, AI, messaging), and manage identity. The server never sees plaintext business data — only routing metadata.

01

Conventions

Base URL
api.vyora.app/v1
Transport
HTTPS · JSON · TLS 1.3
Auth
Bearer JWT · org_id claim
Idempotency
Idempotency-Key hdr

Every mutating request carries an Idempotency-Key (the client-generated record UUID) so a retried sync never double-writes. Every response echoes a request_id for tracing.

02

The encrypted record envelope

Every business record — invoice, product, customer — travels as an envelope. Only the outer fields are readable by the server; body_enc is AES-256-GCM ciphertext.

record_envelope.json
{
  "id": "inv_9f2c…a41",        // client UUID = idempotency key
  "org_id": "org_7712",        // tenant · enforced by RLS
  "type": "invoice",
  "version": 7,               // server-incremented, for conflicts
  "updated_at": "2026-07-16T09:12:04Z",
  "deleted": false,          // tombstone flag
  "body_enc": "base64(AES-256-GCM ciphertext)",
  "nonce": "base64(96-bit IV)"
}
