V Vyora Offline Architecture

Everything works offline. Sync just catches up.

Writes land in a local SQLite database and an outbox queue. A background sync engine flushes the queue to Supabase when a connection returns, then Realtime pushes changes to the company's other devices — conflicts resolved automatically.

02

Local storage layers

Three browser primitives, each with a clear job — plus a service worker so the app cold-starts with no network.

SQLite WASM

The relational core — invoices, items, ledgers, stock. Full SQL with joins powers every list and report, entirely on-device.

OPFS

Origin-private file system holds the SQLite database file and attachments (bill photos). High capacity, durable across sessions, fast synchronous access.

IndexedDB

The sync outbox, cached metadata (business schemas), settings, and session — small async records that need quick key access.

Service Worker · Workbox

Caches the app shell and assets so the PWA opens instantly offline, and drives the Background Sync API to flush the queue after the app is closed.

03

Sync queue (outbox)

Every mutation writes an encrypted, UUID-keyed change record to the outbox. It moves through a small state machine and is applied in creation order.

Change record
{
  "id": "e3b0c442-98fc-1c14…",
  "entity": "invoice",
  "op": "insert",
  "payload": "‹AES-256 ciphertext›",
  "baseVersion": 3,
  "createdAt": 1752624000,
  "state": "pending",
  "attempts": 0
}
State machine
pending → syncing → synced
syncing→failed → retry
Applied strictly in createdAt order per entity Idempotent by UUID — safe to re-send Synced records pruned after acknowledgement
04

Background sync triggers

The queue flushes from several triggers and retries with backoff, so a synced state is reached without the user thinking about it.

Connectivity regained

The online event immediately flushes pending changes.

Background Sync API

The service worker retries even after the app is closed.

Periodic while open

A timer reconciles every few minutes as a safety net.

Manual “Sync now”

The owner can force a flush from the status pill.

Retry policy: exponential backoff — 2s, 4s, 8s… capped at 5 min. After the max attempts a change surfaces as a failed state with a one-tap retry; it is never silently dropped.

05

Automatic conflict resolution

Each record carries a version and updated_at. Resolution is deterministic and needs no user prompt.

ScenarioResolution
Same field edited on two devicesLast-write-wins by highest version / updated_at
Different fields editedField-level merge — both changes kept
Deleted on A, edited on BTombstone wins; edit discarded with an audit note
Stock count changed on bothAdditive CRDT merge — deltas summed, not overwritten
New records inserted offlineNever conflict — client-generated UUID primary keys
Invoice-number collisionServer reassigns the display sequence; UUID stays stable
06

Guarantees

Never blocks

Every action completes locally in milliseconds, connected or not.

Never loses data

Durable in OPFS; the outbox survives reloads, crashes, and restarts.

Encrypted throughout

Payloads are AES-256 encrypted before they enter the queue or the cloud.
