V Vyora Build Roadmap

Design approved — now build in phases

This is a commercial ERP platform, not a billing app. Architecture, design system, and business rules are settled; from here, generate software in well-defined phases — each with a clear definition of done.

01

Monorepo structure

vyora/
├── apps/
│   ├── web/          # Next.js PWA · tenant app
│   └── admin/        # internal admin portal
├── packages/
│   ├── ui/           # design system (shadcn + tokens)
│   ├── core/         # metadata engine · business rules
│   ├── db/           # SQLite WASM · schema · migrations
│   ├── sync/         # offline sync engine
│   ├── crypto/       # AES-256 · key management
│   ├── ai/           # provider router · MCP clients
│   └── config/       # eslint · tsconfig · tailwind
├── supabase/         # migrations · RLS · edge functions
├── e2e/              # Playwright tests
└── .github/          # CI/CD workflows
Turborepo + pnpm workspaces

Shared packages, cached builds, one dependency graph.

Two apps, shared core

Tenant PWA and admin portal both consume ui, core, and types.

Types flow from the DB

Supabase-generated types are the single source of truth end-to-end.
